What happens when the user types "skip"?

Comparing normal RECV flow vs. skip flow — same first steps, diverges at the sheet update

Normal — user types RECV number
Redis state cleared
Both flows delete recv_pending:userId
↓
File re-downloaded from LINE
By messageId stored in Redis
↓
File uploaded to Google Drive
Goes to the correct folder (recv-pos, invoice, or shipping-cost). Returns fileId.
↓
✅ updateSheetLink called
Searches col B for the RECV number.
Writes hyperlink to B / E / H.
For recv-pos: also writes branch + dealer.
↓
✅ บันทึกแล้ว + Sheet updated
File is in Drive AND linked in the sheet.
Skip — user types "skip"
Redis state cleared
Same as normal
↓
File re-downloaded from LINE
Same as normal
↓
File uploaded to Google Drive
Same as normal — file is safely stored in Drive.
↓
✗updateSheetLink — SKIPPED
if (recvNo.toLowerCase() !== 'skip') is false.
Sheet is not touched at all.
↓
✅ บันทึกแล้ว — Drive only
File is in Drive, but sheet has no link.
No way to link it later without re-uploading.
⚠️ Current limitation
📂 The file lands in Drive (correct folder, correct filename) — it is not lost.
📋 The sheet row stays untouched — no hyperlink, no branch, no dealer for that RECV number.
🔗 There is no "link later" command. The bot has no way to take an already-uploaded file and write its Drive link into the sheet retroactively.
♻️ To link it, the user would have to re-send the image and go through the full flow again — or manually paste the Drive link into the sheet.
💡 Possible improvement (v5 idea)
🔢 Add a "link by RECV" command: user types link RECV 988 → bot searches Drive for the most recent unlinked file in that category → writes the hyperlink to the sheet.
📌 Or: when skip is used, store the Drive fileId + category in Redis with a longer TTL (e.g. 24h) so the user can follow up with just the RECV number later.
