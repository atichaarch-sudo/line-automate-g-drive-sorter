Why Each Tool Was Chosen
💬

LINE Messaging API

User interface + file delivery + quick reply buttons

Why LINE

The business already uses LINE daily. Staff send receipts as chat photos — no behavior change needed. The bot fits into existing workflow.

What LINE provides

Webhook events (message)Webhook events (postback)File hosting (Content API)Reply APIPush APIQuick reply buttonsSignature verification

Quick reply — postback actions

How they work

Quick reply buttons fire a new postback webhook event with a custom data payload (up to 300 chars). Category, dealer, date, amount all travel inside this payload — no external state needed for the save step.

The 1-second rule

Constraint

LINE requires HTTP 200 within 1 second for both message and postback events. The entire architecture is built around meeting this deadline.

Key env vars

LINE_CHANNEL_TOKENLINE_CHANNEL_SECRET
▲

Vercel — Serverless Function

HTTPS webhook host + background runner

Why Vercel

LINE needs a public HTTPS URL. Vercel gives one instantly with zero server management. Deploy from CLI, no GitHub required, free on Hobby plan.

The critical feature: waitUntil()

How it works

waitUntil(promise) from @vercel/functions returns HTTP 200 immediately, then keeps the function alive for background work. Both the classify phase and the save phase use this.

Hobby plan limits

300s max duration2 GB memory1M invocations/monthFree

Export style required

// ✅ Required for waitUntil() to work export default { async fetch(request) { waitUntil(classifyAndConfirm(event)); return new Response('OK', { status: 200 }); } }; // ❌ Legacy style — waitUntil() silently ignored module.exports = (req, res) => { res.end('OK'); }
🤖

Gemini 2.5 Flash

Thai document classifier + data extractor

Why Gemini

Files are images or PDFs — you can't classify them with keyword matching. Gemini is multimodal: it reads actual visual content and understands Thai text.

v3 — extracts 4 fields in one call

Single prompt, structured JSON

Instead of just returning a category, Gemini now returns {"category","dealer","date","amount"} — all four fields in one API call. The filename is built from these fields before the confirmation message is sent.

// Example Gemini response: {"category":"order","dealer":"โอเอซิส","date":"29.04.69","amount":"547"} // Filename built from these: โอเอซิส_29.04.69_547฿.pdf

Thai document rules in prompt

invoice → ใบแจ้งหนี้ (standalone bill, no delivery) quotation → ใบเสนอราคา (price proposal before sale) order → ใบสั่งซื้อ, ใบส่งของ, combined ใบส่งของ/Tax Invoice IMPORTANT: ใบส่งของ anywhere = "order" other → anything else

Key env var

GEMINI_API_KEY
🗄️

Upstash Redis

State storage for the dealer-name edit flow

Why Redis

The edit flow spans two webhook events (postback tap + text reply). Vercel functions are stateless — there's nowhere to hold "pending edit" between events. Redis bridges the gap.

Why Upstash (not self-hosted)

Free tier + REST API

10,000 commands/day free. More importantly, Upstash exposes a REST API — so the function uses plain fetch() with no SDK, no npm package, zero added bundle size.

What's stored (TTL 5 min)

// Key: edit:{userId} // Value: { "messageId": "12345678901234", "category": "order", "date": "29.04.69", "amount": "547", "mimeType": "application/pdf" }

Design note

One pending edit per user at a time (userId key). If a second file is sent before the edit completes, the new state overwrites the old one. Intentional — single-user shop bot.

Key env vars

UPSTASH_REDIS_REST_URLUPSTASH_REDIS_REST_TOKEN
☁️

Google Drive API

Final storage destination

Why Drive

The business already uses Drive. Files land where staff already look — no new system to learn.

Why OAuth2 refresh token (not Service Account)

Service Account was blocked

Google's org policy iam.disableServiceAccountKeyCreation blocked key creation on all available GCP projects.

OAuth2 refresh token — the fix

Authenticates as your own Google account. The refresh token never expires unless revoked. Three env vars replace the entire service account JSON file.

Folder routing

LINE Signature Verification

Security gate — first thing checked on every request

Why it matters

Your webhook URL is public — anyone can POST to it. Without signature verification, forged postback events could trigger Drive uploads.

How it works

// LINE signs every request: // x-line-signature = base64(HMAC-SHA256(rawBody, channelSecret)) // Function re-computes and compares: if (computed !== x-line-signature) → return 403

Why Web Crypto API (not Node crypto)

No extra dependency

crypto.subtle is built into the Vercel runtime. Zero bundle cost.

The Critical Design Decision — Why the Architecture Looks This Way

⚠️ The Core Constraint: LINE's 1-Second Timeout

LINE requires HTTP 200 within 1 second — for both message and postback events. The actual work (download + classify + upload) takes 5–30 seconds. waitUntil() handles both fast paths so LINE never times out.

Without waitUntil() — What Would Break

❌ Process first, then respond

Download + Gemini + send confirmation all run before returning HTTP 200. Takes 5–10 seconds.

// Response arrives at LINE after ~8s // LINE gave up at 1s and already retried // Bot classifies the same file twice // Two confirmation messages arrive

✅ Respond first, process in background

HTTP 200 returned in ~50ms for both message and postback events. All heavy work runs inside waitUntil().

// Message event: waitUntil(classifyAndConfirm(event)); return new Response('OK', { status: 200 }); // <50ms // Postback event: waitUntil(handlePostback(event)); return new Response('OK', { status: 200 }); // <50ms
